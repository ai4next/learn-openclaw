# Learn OpenClaw — 从零构建开源 AI 代理

> **智能来自模型，而非外部代码。Harness 是车辆，模型是驾驶员。**

**Learn OpenClaw** 是一个循序渐进的实践教程，帮助你理解并构建 [OpenClaw](https://github.com/openclaw) 风格的 AI 代理框架。你将从一个 20 行的循环起步，最终构建出一个拥有工具、技能、记忆、通道、定时任务、子代理等完整功能的 AI 代理。

**核心小巧，边缘扩展。**

## 为什么选择 OpenClaw？

大多数"AI 代理框架"是鲁布·戈德堡机械——将提示词拼凑伪装成基础设施。OpenClaw 采取了不同的思路：

- **模型就是代理本身。** 核心循环是 `while True`——模型通过 `stop_reason` 自主决定下一步操作。
- **Harness 起赋能作用，而非控制作用。** 工具、技能、记忆和通道都是被动资源，由模型自主选择使用。
- **核心保持精简，在边缘扩展。** 代理循环刻意保持最小化。新能力以工具、技能或通道的形式添加，而非侵入核心运行时。
- **优先重复，避免过早抽象。** 通道和子系统可以重复模式，而无需共享复杂的基类。

本项目实现的是 **harness**——即让模型发挥作用的环境、工具、知识和接口。

## 快速开始

```bash

python chapters/01_agent_loop.py
```

## 设计原则

> **循环是神圣的。永远不要改变它。在它周围分层构建机制。**

1. **信任模型。** 给予正确的工具和知识，模型会做出正确的决策。不要用僵化的流程束缚它。
2. **构建环境，而非提示词。** 打造环境和工具。让模型自己制定计划。
3. **渐进复杂。** 从最小化起步。每次只增加一种机制。每节课都是一个可理解的变化增量。
4. **自包含课时。** 每个代理文件独立运行。课时之间不共享状态。
5. **Bash 就是一切。** Shell 工具赋予了模型无限的能力。其他都是锦上添花。

## 本项目不涉及

- 完整的事件钩子和生命周期回调
- 权限治理和审批工作流
- 跨实例会话复制
- 生产部署编排

这些是重要话题，但属于生产框架的范畴，而非学习项目的目标。
